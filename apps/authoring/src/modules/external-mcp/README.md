# modules/external-mcp —— Codex 远程 Agent Builder

这个模块在 Authoring API 内提供无状态 Streamable HTTP MCP 和独立的 OAuth 2.1 授权面。浏览器授权页只用现有邮箱验证码 Session 确认用户；Codex 只获得绑定精确 MCP resource 的短期 Bearer Token，数据库只保存令牌摘要。

## 文件

- `routes.ts` 注册 RFC 9728 资源发现、RFC 8414 授权服务器发现、动态客户端注册、授权页、令牌、MCP 和公开安装引导路由，并限制正文和调用频率。
- `handlers.ts` 渲染不加载第三方脚本的授权与安装 HTML，处理 OAuth 响应，校验 MCP transport 请求，并分发 JSON-RPC 工具。
- `service.ts` 生成高熵一次性凭据，执行 PKCE S256、scope 和 resource 校验，只接受 Codex 当前使用的 `127.0.0.1` loopback callback 并只放宽端口。IPv6 literal 无法作为 CSP Level 3 的精确 `form-action` source，因此当前明确拒绝，不能通过放宽到任意 `http:` 回调规避。动态注册对规范元数据计算 SHA-256 digest；临时监听端口与 URI 集合顺序不进入 identity。
- `repo.ts` 保存动态客户端、摘要化授权请求、一次性授权码和摘要化令牌；刷新令牌按 family advisory lock 串行，发生重放时撤销整个令牌家族。API 不能直接插入或删除 client，只能调用迁移定义的受控注册与有界清理函数。
- `runtime-client.ts` 只经固定集群内 Runtime origin 转发当前请求的 Bearer Header，按共享 schema 校验 Studio UI、Agent Test 技术状态、质量状态和发布资格，并把 Runtime 错误收敛成安全失败。解析兼容旧 Runtime 缺少质量字段的响应，并将其视为未复核且不可发布。
- `agent-builder-app.ts` 提供 MCP Apps 标准的内联 Agent Builder 卡片资源，先完成
  `ui/initialize` / `ui/notifications/initialized` 生命周期，再接收工具数据。卡片只展示模型
  已经核验的阶段数据，按钮优先通过标准 `ui/message` 把用户选择送回当前对话，并在宿主
  未声明该能力时 feature-detect OpenAI 兼容消息桥；卡片本身不创建、复核或发布业务对象。
- `tools.ts` 暴露显式 Project ID 的无状态 Agent Builder 工具和只读展示工具，复用现有 Agent Project service 和共享 schema，不保存进程内 TargetState。`record_agent_test_review` 只能在当前 Codex 任务中得到用户对三类案例的明确质量确认后调用，服务端会把当前 OAuth 用户冻结为 reviewer。Test 与 Release 结果同时返回可点击的 Runtime 资源链接。

## 协议边界

MCP 资源是规范 origin 下的 `/api/external-mcp/mcp`，与 Project Agent 公开页面共用同一个 `EXTERNAL_MCP_PUBLIC_ORIGIN`。本地开发该 origin 是 Vite `:5173`，由 Vite 把 `/api`、`/.well-known` 和 `/codex-plugin` 代理到 Authoring `:3000`；直连 `:3000` 不能代表完整公开页面。未认证 GET 与 POST 返回带路径版 protected-resource metadata 的 Bearer challenge；根路径和路径版 metadata 返回相同资源文档。授权、换码和刷新都必须携带同一个精确 resource，客户端必须使用 S256 PKCE。

授权确认页的内容安全策略只允许表单提交到自身和本次请求已经校验过的精确 loopback origin，使 303 回调可以返回 Codex，同时不开放其他主机或端口。成功页使用 `strict-origin` 保留同源 POST 的 Origin 校验；错误页继续使用 `no-referrer`。

当前远程工具面固定为二十三项。前二十项保持原有十八项提取与 Agent Builder 工具以及 `create_project_agent_share`、`read_project_agent_share` 的顺序和契约；末尾追加 `create_codex_agent_share`、`read_codex_agent_share` 与只读 `prepare_codex_agent_run`。默认 Creator Bootstrap 在检测/安装前只从当前顶层任务里用户实际表达且可见的需求、约束和结论生成 sanitized draft，此时 helper、文件、tracked guidance、Git 与 Git network 调用数都为零；`recommended_plugins`、`in-app-browser-context`、`heartbeat`、`app-context`、`codex_delegation`、`source_thread_id` 等 Host wrapper 不属于用户需求。只有四项新工具与 official Plugin `>=0.7.0`/Test MCP metadata 初始都满足时才 stay current，此分支不主动登录；只有工具明确返回 authorization 错误时才恰好登录一次并只重试原调用。否则 Creator 先冻结 Host-safe `combo.creator-bootstrap-handoff/1`，完成安装或升级与最终 metadata 校验后、任何 `create_thread` 前用绝对 bundled CLI 恰好完成一次 Codex-managed OAuth，失败或取消时零任务创建；成功后才在 same saved Project 续跑。子任务 readiness 后才只读 source Git/tracked guidance、完整重显并等待确认；若缺工具或 readiness 失败就报告 catalog blocker，禁止再次登录或重建任务。确认后创建并立即回读同一 URL 的 `combo.codex-agent-share/1`；服务端只校验字段形状，不能证明 instructions 已脱敏或不含原文。新 manifest 没有独立 raw task、threadId、messages、session、路径、transcript 或 secret-bearing 字段，`rawStored=false` 只描述没有独立 raw task blob。新链路不调用提取、Capability、Agent Project 或旧 Project Agent 工具。两类公开 HTTP 页面/API 都由持链接者匿名读取，MCP transport 本身仍需 OAuth，但读取不按 owner 过滤。它不是账户授权或 OAuth token；但它是未列出的公开定位链接，持有即匿名可读，请按公开内容处理。

Codex Agent 接收端也先检查四工具与 Plugin/Test MCP metadata；初始全满足则 stay current 且不主动登录，只有可调用工具明确返回 authorization 错误时才恰好登录一次并只重试原调用。否则先冻结 Host-safe `combo.receiver-bootstrap-handoff/1`，完成安装或升级和 final metadata 后、任何 `create_thread` 前用绝对 bundled CLI 恰好完成一次 Codex-managed OAuth；失败或取消时零任务创建，成功后正式 Host 才用 `target:{type:"projectless"}` 创建顶层续跑任务，不能借用 Creator 的 same-Project handoff。子任务缺工具或 readiness 失败只能报告 catalog blocker，禁止再次登录或重建任务；parse、readiness、完整读取/重显后，才在 assistant `agentMessage`（`phase=final_answer`）回证 exact `COMBO_RECEIVER_HANDOFF_READY`。父任务不能从 `userMessage`、`codexDelegation`、tool input、echo 或 handoff 输入匹配 marker，只在证据之后的该 assistant 输出回证成功时立即导航显示它。Handoff 本身不算确认。Creator handoff 采用同一证明规则，不能从 creatorHandoff 输入匹配 `COMBO_CREATOR_HANDOFF_READY`。接收端核对返回的 schema 与 manifest SHA-256 是否等于 copyPrompt 固定的期望摘要；Authoring 仓储每次读取都解析 manifest，并用共享 `canonicalJson` 对数据库摘要做失败关闭校验。接收端展示一个仍显示公开 name 的 manifest 总览和完整有序的 starter prompts，让用户用对应 action 按一基序号完成同一次恢复运行确认。Action 的 user-role message 由共享 renderer 生成，只绑定 digest、总数 M 与一基序号 N，不复制 name 或任何 manifest 自由文本；确认解析会比较整个 card snapshot，因此 URL、name、digest、总数、顺序或 N 变化都失败关闭。系统按序号精确取 manifest starter，先调用 `prepare_codex_agent_run`，校验四项回显与权威 run envelope；成功前不得写本地。随后才由已安装 Skill 调用 Plugin packaged helper 的 `restore` mode，把固定 commit 恢复到 `$HOME/Developer/Combo-shared-projects` 下 commit 前十二位加随机 nonce 的新 ASCII child，路径不能来自 manifest 文本，并独立核对 HEAD、tree 与 clean 状态。注册时把 exec tool workdir 设为已验证 target，只执行一次固定 `"/Applications/ChatGPT.app/Contents/Resources/codex" app .`，不得把路径插入 command string；正式 Host 的 `list_projects` 最多顺序调用三次以按 canonical exact path 唯一匹配，任一次 Host error/timeout、未命中或多重命中都阻断。

正式 Agent task 的唯一首消息是 `prepare_codex_agent_run` 返回、由共享 `renderCodexAgentRunEnvelope` 生成的 Host-safe flat compact JSON。V1 sourceRef 收窄为 shell-safe 的完整 ASCII heads/tags ref；V0 ref 契约不变。`expectedSourceRef` 只记录远端 provenance；恢复后的当前本地 ref 必须是 `refs/heads/combo/project-agent/<commit 前十二位>`，不能拿它与 expectedSourceRef 比相等。Raw `COMBO_CODEX_AGENT_RUN/1` 是显式 advanced launch 命令而非此前确认的证明；终端 Plugin 在任何 Git preflight、instructions 或 starter 执行前必须恰好调用一次 `prepare_codex_agent_run`，并要求四项回显及 runEnvelope 与当前输入完全一致，失败时零执行。复核通过后 Agent 才核对 origin repository、deterministic restore ref、commit、tree 与 clean，再执行完整 instructions 和用户选择的 starter；此后不得再次读取分享、恢复目录、调用 `codex app`、导航或创建下一层任务。Plugin outer run route 只有在 chosen starter 实际开始后，才由 assistant `agentMessage`（`phase=final_answer`）报告 exact `COMBO_CODEX_AGENT_STARTED:<manifestSha256>`；父任务排除 `userMessage`、`codexDelegation`、tool input 与 echo，精确核对本次分享摘要，仅在 preflight 成功且绑定摘要的 marker 回证后自动导航显示正式 Agent，失败时不导航。全链路零重启，任何目录或 Host 条件不满足都准确阻断。

旧 Agent Builder 展示工具只把已经核验的数据渲染为 MCP App，不保存选择；`facts[].value` 最长一万字符，可完整展示最长八千字符的 Creator instructions。MCP 不保存 TargetState；所有 Project、Revision、Test 与发布操作都显式携带资源 ID。质量复核按案例分别保存执行终态和质量结论，整体质量状态只由服务端派生；最终发布确认不会修改复核。发布 Revision 只从技术通过、质量可发布且仍匹配当前 Head 的 Test 服务端推导。

Studio UI 与 Agent Test 仍由 Runtime 执行。Authoring 只把当前 access-token 通过固定的集群内 HTTP 路由转发；Runtime 只能只读 `oauth_access_tokens` 摘要表并再次校验 resource、有效期、账号和所需 scope，不能读取客户端、授权请求、授权码或 refresh token。浏览器 Cookie 从不进入该链路。

授权 GET/POST 与 DCR 每 IP 每分钟最多 30 次，Token 每分钟 60 次，MCP GET/POST 每分钟 300 次。所有生产副本通过同一 `redis_hot` 共享计数、按发布环境隔离 key，Redis 故障时失败关闭。DCR、授权 GET/POST、Token 和 MCP GET/POST 共用一个进程内低频调度窗，任一活跃流量都可每分钟触发一次数据库有界清理；每类状态每次最多删除 100 条。未过期但已使用的 refresh token 保留到过期，以继续检测 replay。

DCR 使用忽略 loopback 临时端口的 canonical registration digest 去重；Codex 重启或端口变化会复用同一 `client_id`，同时响应本次 URI。数据库 advisory lock 把复用、容量恢复、计数和插入串行，client 总量硬限制为 4096。满额时只淘汰超过十分钟、最近未使用且对授权请求、授权码、access token、refresh token 均无引用的最旧 client；没有安全候选则失败关闭。普通维护只清理超过三十天且无任何引用的 client。

`/codex-plugin` 当前只在 Test 环境提供固定 `codex/combo-plugin-v2-ui` 的 Creator Bootstrap 0.7 安装命令。状态机先同时读取 Marketplace 与 Plugin；同名异源、Plugin 存在但 Marketplace 缺失或无效版本立即停止。官方 Marketplace 已存在而 Plugin 缺失/过旧时先 upgrade Marketplace、刷新 metadata；无论 Marketplace 初始是否存在，只要当前已确认 official source 且 Plugin 仍缺失，就恰好 add Plugin 一次。fresh install 固定按 add Marketplace、重读并确认 source、add Plugin、最终检查执行。功能门要求 Plugin 有效 semver `>=0.7.0` 且已安装启用，`mcp get combo` 的 name、enabled、disabled_reason、transport.type 和 Test URL 全部精确匹配；当前 Test 候选验收另要求 exact 0.7.0。Creator 只有初始工具/metadata不全时才在 final metadata 后恰好执行一次 Codex-managed OAuth，再通过正式 Host 的 `list_projects` 和精确 project/local `create_thread` 留在同一 saved Project；失败或取消时零任务创建。clientThreadId-only 失败关闭，ready thread/host 经 wait、list、read 与 marker 回证后自动导航；续跑任务不再登录或重建。初始全满足的 stay-current 分支不主动登录，只有工具明确返回 authorization 错误时才恰好登录一次并只重试原调用。不要求用户手动 shell、二次粘贴或重启。0.7.0 继续保留旧 Project Agent 读取工具，因此已有 V0 copyPrompt 仍可执行。V1 create 只允许 Test；Preview/Production 仍可公开 read，但不会铸造硬编码 Test 的新链接。
