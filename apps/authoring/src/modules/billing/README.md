# modules/billing — 余额充值与支付确认

这个模块管理用户钱包读取、内部充值订单、乐收赢支付通知和主动查单补偿。充值金额由调用方在 HTTP 边界直接提交，进程内不配置套餐；乐收赢只完成外部收款。免费次数与 Agent 使用扣费由 runtime 管理。

## 文件

- `types.ts` 定义内部充值订单、钱包、仓储端口和本模块固定错误。
- `repo.ts` 实现充值订单、支付尝试、回调事件、钱包与不可变资金流水的 PostgreSQL 事务。充值入账在一个事务中完成订单成功、钱包加款和流水追加；平台订单号写入后不可被慢响应覆盖，回调或查单已经推进的状态也不能被更早发出但更晚返回的预下单结果降级。到期的支付动作会按有界批次清空。按用户的数据库 advisory lock 同时限制最多三笔未决充值及每小时十笔新订单，保证多副本下更换 intent 也不能无限触发网关 POST。
- `service.ts` 编排幂等创建、网关下单、通知处理和查单租约。一个充值意图、内部订单和支付流水绑定后保持不变；预下单超时或进程退出时只查原流水，失败或关单后再次充值必须使用新的充值意图。未通过验签的通知不会写入回调事件表。
- `reconcile.ts` 在 API 进程中按配置周期清理到期支付动作并领取待查订单。每笔订单最多主动查询 120 次且不超过 24 小时，之后停止自动查询但仍接受可信成功回调；多副本由 PostgreSQL 租约协调，单进程不重叠执行，关闭应用时等待当前轮结束。网关开关关闭时仍会清除过期支付动作，但不会请求网关。
- `handlers.ts` 校验本地 HTTP DTO，并把业务结果映射为成功信封或安全错误。
- `routes.ts` 注册钱包、充值订单和支付通知端点。浏览器写入使用 Cookie 与精确来源守卫，网关通知不依赖 Cookie 或 Origin。

## 上下游

路由由 `bootstrap/routes.ts` 挂到 `/api/v1`。handler 与后台查单调度器使用 Fastify 注入的 PostgreSQL、充值配置和支付网关端口。表结构由追加迁移维护；本模块不保存机构密钥、原始回调或完整网关响应。
