# Agent Gateway

本目录实现 Creator-hosted Agent VNext 的 Worker WebSocket Gateway。Gateway 只处理连接、握手授权、每连接严格顺序、重复帧重放、会话替换和有界传输；它不保存 Prompt、回答或权威终态，也不在内存中假装替代 PostgreSQL、Worker SQLite 或 Broker Outbox。

`src/gateway.ts` 提供真实 WebSocket 服务和持久化端口。`src/postgres-authority.ts` 是真实 PostgreSQL authority：它一次性消费 P-256 Device Challenge，验证 Worker/Runtime/Protocol/Isolation exact indexed profile，把已验证注册能力的 canonical digest 固定到短期 Session，并持久化 connection-bound Lease/Fence、严格 sequence receipt、Outbox ACK 和 Cloud-time Heartbeat。握手必须携带由共享 Protocol 真源定义的单一 `brokerContractDigest`；旧客户端缺字段会在调用 authority 前被 strict parser 拒绝。只有 Device P-256 签名有效后，Gateway 才用共享 `BrokerRegistrationCapabilitiesSchema` 校验注册值，并在创建 Session/Lease 前强制 registration、handshake 与同一 profile 逐项相等。任何 contract 缺失、不匹配或未命中 exact profile 都会原子消费 Challenge、把 Deployment 持久化为 `BLOCKED`、记录稳定兼容错误审计，且 Session/Lease 都保持 0；伪签名则整笔回滚，不消费 Challenge、不写 BLOCKED 或审计。健康 Heartbeat 在同一事务续租并固定返回 `[lease.grant, CLOUD_COMMITTED ACK]`；Worker 必须先持久化 grant 才会看到 ACK。`lease.accepted`/`lease.renewed` 以原 grant messageId 为 correlationId，并把该 ID 与持久化的 exact leaseId、Fence、Lease expiry 一起校验后才把 grant 标记为 PERSISTED；它们只返回 ACK，不再次续租，避免反馈环。每个写事务在 mutation 前取得稳定 operation advisory lock，并在同一事务写入有界 operation receipt；COMMIT transport 不确定时只允许新连接取同一锁并读取 receipt，绝不在已提交 COMMIT 后发送 ROLLBACK 或用新 operation id 自动重做。Heartbeat、Version撤销和business projector返回的`SECURITY_BLOCK`共享同一隔离链：Gateway在返回前原子撤销受影响Lease、Session及Deployment内仍非终态的execution capability，把Deployment标成BLOCKED，并持久化Cloud ACK与`lease.revoke SECURITY`供精确重放；终态Invocation的历史Capability不补写revoked timestamp但已无法再次执行，自然Session replacement仍保留旧Invocation capability供对账。业务 Invocation 事件先严格验证当前外层 Session、Lease、Deployment 和 Fence，再只按同 Creator、同 Deployment、同 Installation 路由到同transaction projector；事实内不可变的原始Lease、Fence、Capability、Version、Snapshot与prepared/started/confirmed-failed/full-succeeded fact JCS digest仍由数据库/Cloud projector精确验证。Succeeded DB preflight在调用fresh-only sealer前终止exact/security path，缺projector会fail closed，不能用一条receipt冒充业务状态已提交。

`src/config.ts`、`src/runtime.ts` 与 `src/processes/gateway.ts` 组成严格 Test-only 的可执行入口。启动前必须固定 `combo_agent_broker` 最小角色、0030 lifecycle-v2 exact schema/function contract、当前 Broker contract、显式 Worker/Codex/Isolation profile 和 release tuple；既有四个 compatibility JSON 数组必须等长并按索引组成 exact profile，Worker version 是不可重复的 profile key，不能把四个数组当成独立 allowlist 产生 Cartesian 混搭。readiness 通过只授予 isolated Broker 的 SECURITY DEFINER predicate 检查 0030，不读取 migration ledger；`/ready` 动态复验，SIGTERM 先撤 readiness 再有界关闭 WebSocket 与数据库池。publisher 默认关闭，启用时还必须给出非空 Deployment allowlist 和绝对路径的 Test-only mounted keyring；缺任一 USER/ASSISTANT sealer 都会在创建 Pool 前拒绝启动。可执行入口把真实 `PostgresCloudJournal` 注入 prepared/started/succeeded/failed/cancelled inbound projector，并把 payload-v2 prepare/start publisher 接到真实 claim 路径；这不代表 Production KMS 或 signing authority 已完成。

Gateway 在事务确认前不会激活连接。所有 authority 调用和发送操作都有硬超时；调用方断开会 abort 底层事务，若 COMMIT 已经越过不可取消边界，Gateway 等待有界 authoritative outcome，随即补偿关闭 Session/Lease，绝不会在 deadline 后激活连接或发送 ACK。同一实例是单次 start/stop 生命周期，滚动升级由进程编排创建新实例。公网 WSS 由 Test Ingress 终止 TLS；Nginx 只把 exact `/v1/worker/connect` 交给 Gateway，不把 `/v1/worker/*` 广泛路由给 Runtime 或 Authoring。

运行 `pnpm -F @cb/agent-gateway test` 执行传输契约测试。测试覆盖错误路由和 Origin、握手时限、缺失 contract digest 在 authority 前拒绝、一次性 Challenge、全局 Session ID 唯一性、严格 sequence、exact replay、gap、会话替换、过期/畸形/超限帧、authority 超时、COMMIT/断连竞态、端口失败以及有界关闭。wire corpus 的 N-1/N/N+1 还会分别进入真实回环 handshake 与 established frame；N+1 target payload 不进入 authenticate/accept/replay/gap，连接清理仍会正常调用 `closeSession` lifecycle。该证据只对齐当前 runtime 与 Broker contract，不覆盖 TLS/public WSS、fragmentation、负载或 Production。显式设置 `CREATOR_AGENT_GATEWAY_PG_TEST=1` 与 disposable PostgreSQL 角色 URL 后，`src/postgres-authority.pg.test.ts` 与 `src/postgres-broker-outbox-publisher.pg.test.ts` 会运行真实 P-256 + PostgreSQL 纵向测试；后者从真实 Consumer create v2 产生 Outbox，覆盖 claim COMMIT 响应丢失恢复、同 Session 自然 1 秒 exact retry、每 Creator 全局 Alpha WIP=1、replacement current re-envelope、先到 PERSISTED ACK 的 durable receipt，以及只有 `conversation.ready` 才把 Outbox 推进到 ACKED。普通 test 不把 skip 冒充 PG 证据。

Gateway 不导出接受任意 Envelope 的直接 dispatch API。Phase A 提供默认关闭的 Test-only `conversation.open` 与 lifecycle publisher：启用时必须注入 durable claim authority；每个 claim 在 Creator 全局 WIP advisory 内按 Deployment advisory、current Session/Lease、exact Outbox 的顺序锁定，并在 Outbox attempt、current delivery 与 operation receipt 提交后才返回 wire frame。首次 delivery 至少保留 3 秒 Cloud-authoritative wire 窗口，已提交的同 Session delivery 只在仍有 1 秒窗口时 exact retry。`messageId` 与原始 immutable authority 跨 Session 稳定，外层 connection/Session/Lease/Fence 按 current authority 重封装；同 Session 重试保持 exact bytes。Worker 的 `PERSISTED` 只抑制该 Session 重发且不会 ACK Outbox，replacement Session 先重放 ACK 时只保存 UUID/枚举 receipt，再由 publisher 创建已 PERSISTED 的 current delivery并仍发送 current re-envelope；conversation.open 只有 durable `conversation.ready` projector 才原子推进 Conversation 与 Outbox。

payload-v2 lifecycle publisher 只开放 `invocation.prepare` 与 `invocation.start`：首次 claim 在同一事务内写入严格校验的 JSON projection、canonical UTF-8 text 和 digest，operation receipt 只保存 Session/command/sequence/digest 引用；提交后和 COMMIT response loss 都经 owner-scoped RLS read-only transaction 重新读取 exact canonical frame。同 Session replay 不调用 sealer，replacement Session 才重新密封 USER ciphertext；start 必须携 predecessor prepare 的完整 capability 并重新计算 digest/binding。`invocation.cancel` outbound producer、ACK retirement 与 terminal arbitration 明确留给后续 0031，不能把当前 nullable schema 铺路当成 cancel 产品闭环。Preview/Production 仍被配置和数据库双重拒绝。

当前已证明本机 Test-only `E2 PostgreSQL authority + E2 file SQLite + E3 loopback WebSocket` 的 `conversation.open → PERSISTED → replacement re-envelope → conversation.ready → ACKED` 混合纵向链路，以及注入真实`PostgresCloudJournal` projector时prepared/started的`APPLIED → same-source conflict → durable SECURITY_BLOCK ACK + lease.revoke` PostgreSQL纵向链；started证据同时固定runtime handles、dispatch receipt、sandbox attestation与late RECONCILING root。Gateway PG corpus还包含confirmed FAILED与full SUCCEEDED的fresh/exact/body-conflict、双向terminal-type conflict、receipt replay和统一security isolation。Success exact re-envelope的新wire ciphertext不触发二次sealer，alert/receipt不保存wire ciphertext；mounted keyring 只证明 Test adapter，不证明真实KMS。Gateway没有Host/Codex调用端口，sealer与start-command零增量断言不能替代Worker侧no-second-dispatch计数。此外还没有证明Redis presence、真实公网TLS/NAT、K3s NetworkPolicy、两副本rollout、Production bootstrap、完整cancelled/expired terminal authority或云端故障恢复，不能据此宣布Gate 3/4或完整10.6完成。

`src/lifecycle-outbound.ts` 是产品侧严格 payload-v2 source/delivery codec 与 USER sealer port；`src/test-keyring.ts` 只实现 mounted Test adapter，使用同一文件描述符、`O_NOFOLLOW`、owner/mode/size、duplicate-key 与 fatal UTF-8 检查。`src/postgres-lifecycle-publisher.pg.test.ts` 只在同时设置 `CREATOR_AGENT_GATEWAY_LIFECYCLE_PG_TEST=1`、专用 `CREATOR_AGENT_GATEWAY_LIFECYCLE_PG_URL` 和 `CREATOR_AGENT_GATEWAY_LIFECYCLE_PG_ISOLATED=1` 时运行，并在任何 fixture 写入前强制 PostgreSQL `cluster_name` 精确等于 `combo-vnext-r3-ephemeral`；普通或共享 `DATABASE_URL` 永远不会被该测试写入。
