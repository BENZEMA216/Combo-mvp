# Agent Gateway 源码

`gateway.ts` 管理真实 WebSocket 生命周期，并把所有权威读写委托给 `AgentGatewayAuthorityPort`；它不导出绕过 Outbox/Lease 的任意 dispatch。strict 握手 parser 要求单一 `brokerContractDigest`，因此旧缺失字段不会到达 authority。`postgres-authority.ts` 用最小权限 Pool 落地 Challenge、固定注册能力 digest 的 Session、Lease/Fence、Cloud-time expiry、sequence/ACK、Heartbeat 的 `lease.grant → ACK` durable transaction、grant messageId + Lease/Fence/expiry 精确确认，以及 advisory-lock + operation-receipt COMMIT 结果恢复；它先验证 Device 签名，再用共享 `BrokerRegistrationCapabilitiesSchema` 强制 handshake/registration/policy 三方 contract digest 相等，失败原子落 `BLOCKED` 与 `BROKER_CONTRACT_INCOMPATIBLE` 且不创建 Session/Lease，伪签名则零写入。Heartbeat 仍要求 active Invocation 绑定当前 Lease/Fence，业务 Invocation 事实则允许同一 Installation 重连后用新传输 Lease 提交旧执行 Lease 的不可变事实。Gateway 只验证当前传输 authority 和 Invocation 的 Creator、Deployment、Installation 路由，`GatewayBusinessEventProjector` 在同一 transaction 中继续验证事实内的原始 Lease、Fence、Capability、Version、Snapshot 和 digest。Gateway 发现安全撤销、Installation 撤销或 Immediate 下线时会调用数据库单一跨 Consumer authority 撤销该 Deployment 的非终态 execution capabilities，自然 Session replacement 不做这种撤销。

默认关闭的 Phase A publisher 与 inbound accept 共用每 Session 串行链；authority 只有在 current authenticated TEST Session/Lease、每 Creator 全局 oldest live Alpha command、至少 3 秒 wire 窗口、exact Outbox delivery 和 operation receipt 已提交后才返回 `conversation.open`。断连只丢本次发送机会；claim 后 Gateway 固定在 1 秒后再次 pump，使自然 same-Session retry 不依赖较长的 idle poll。跨 Session 保持 command `messageId`、logical body 与原始 `openAuthority`，但用 current outer authority 重封装；replacement 的 durable PERSISTED ACK 可以先写 identifier-only frame receipt，再初始化 current delivery 的 PERSISTED 状态，Outbox 仍必须等待 `conversation.ready`。`gateway.test.ts` 使用真实回环 socket和确定性 fake 验证默认关闭、commit-before-send、断连/替换与定时器取消；`postgres-broker-outbox-publisher.pg.test.ts` 使用真实 Consumer API/PG roles 验证 claim/receipt/WIP/ready 收敛。测试中的显式 feature option 尚未接到 `main`、Docker 或 K8s；它不代表 Redis、TLS Ingress、NAT、远程 Worker、Production publisher 或云部署已完成。
