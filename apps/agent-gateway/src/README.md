# Agent Gateway 源码

`gateway.ts` 管理真实 WebSocket 生命周期，并把所有权威读写委托给 `AgentGatewayAuthorityPort`；它不导出绕过 Outbox/Lease 的任意 dispatch。strict 握手 parser 要求单一 `brokerContractDigest`，因此旧缺失字段不会到达 authority。`postgres-authority.ts` 用最小权限 Pool 落地 Challenge、固定注册能力 digest 的 Session、Lease/Fence、Cloud-time expiry、sequence/ACK、Heartbeat 的 `lease.grant → ACK` durable transaction、grant messageId + Lease/Fence/expiry 精确确认，以及 advisory-lock + operation-receipt COMMIT 结果恢复；它先验证 Device 签名，再用共享 `BrokerRegistrationCapabilitiesSchema` 强制 handshake/registration/policy 三方 contract digest 相等，失败原子落 `BLOCKED` 与 `BROKER_CONTRACT_INCOMPATIBLE` 且不创建 Session/Lease，伪签名则零写入。Heartbeat 仍要求 active Invocation 绑定当前 Lease/Fence，业务 Invocation 事实则允许同一 Installation 重连后用新传输 Lease 提交旧执行 Lease 的不可变事实。Gateway 只验证当前传输 authority 和 Invocation 的 Creator、Deployment、Installation 路由，`GatewayBusinessEventProjector` 在同一 transaction 中继续验证事实内的原始 Lease、Fence、Capability、Version、Snapshot 和 digest。Gateway 发现安全撤销、Installation 撤销或 Immediate 下线时会调用数据库单一跨 Consumer authority 撤销该 Deployment 的非终态 execution capabilities，自然 Session replacement 不做这种撤销。`gateway.test.ts` 使用真实回环 socket 和确定性 fake 验证网络竞态；`postgres-authority.pg.test.ts` 只有在显式 PG gate 下才证明真实数据库纵向链路。两者都不代表 Redis、TLS Ingress、NAT、远程 Worker、Broker Outbox publisher 或云部署已完成。
