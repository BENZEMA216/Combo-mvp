# Agent Gateway 源码

`gateway.ts` 管理真实 WebSocket 生命周期，并把所有权威读写委托给 `AgentGatewayAuthorityPort`；它不导出绕过 Outbox/Lease 的任意 dispatch。strict 握手 parser 要求单一 `brokerContractDigest`，因此旧缺失字段不会到达 authority。`postgres-authority.ts` 用最小权限 Pool 落地 Challenge、固定注册能力 digest 的 Session、Lease/Fence、Cloud-time expiry、sequence/ACK、Heartbeat 的 `lease.grant → ACK` durable transaction、grant messageId + Lease/Fence/expiry 精确确认，以及 advisory-lock + operation-receipt COMMIT 结果恢复；它先验证 Device 签名，再用共享 `BrokerRegistrationCapabilitiesSchema` 强制 handshake/registration/policy 三方 contract digest 相等，失败原子落 `BLOCKED` 与 `BROKER_CONTRACT_INCOMPATIBLE` 且不创建 Session/Lease，伪签名则零写入。Heartbeat仍要求active Invocation绑定当前Lease/Fence，业务Invocation事实允许同一Installation重连后用新transport Lease提交旧执行Lease的immutable fact。Gateway只验证当前transport authority与Invocation的Creator/Deployment/Installation路由；prepared/started/confirmed-failed/full-succeeded DB authority继续验证原始Lease/Fence/Capability/Version/Snapshot、runtime/attestation、terminal components与JCS digest。Succeeded preflight让exact/security outcome在fresh-only sealer前终止；只有FRESH才经可中止sealer认证transport ciphertext并进入DB finalize。若projector返回durable`SECURITY_BLOCK`，authority会在同一事务提交alert后的Cloud ACK、frame/operation receipt和sequence，并撤销Lease/Session及Deployment内仍非终态的Capability、把Deployment置BLOCKED、发送可精确重放的`lease.revoke SECURITY`；已进入FAILED/SUCCEEDED等终态的Capability虽不补写revoked timestamp，但状态机已使其不可执行。transport sequence冲突仍走独立`SEQUENCE_CONFLICT`审计。自然Session replacement不做这种安全撤销。

默认关闭的 Phase A publisher 与 inbound accept 共用每 Session 串行链；authority 只有在 current authenticated TEST Session/Lease、每 Creator 全局 oldest live Alpha command、至少 3 秒 wire 窗口、exact Outbox delivery 和 operation receipt 已提交后才返回 `conversation.open`。断连只丢本次发送机会；claim 后 Gateway 固定在 1 秒后再次 pump，使自然 same-Session retry 不依赖较长的 idle poll。跨 Session 保持 command `messageId`、logical body 与原始 `openAuthority`，但用 current outer authority 重封装；replacement 的 durable PERSISTED ACK 可以先写 identifier-only frame receipt，再初始化 current delivery 的 PERSISTED 状态，Outbox 仍必须等待 `conversation.ready`。`gateway.test.ts` 使用真实回环 socket和确定性 fake 验证默认关闭、commit-before-send、断连/替换与定时器取消；`postgres-broker-outbox-publisher.pg.test.ts` 使用真实 Consumer API/PG roles 验证 claim/receipt/WIP/ready 收敛。Test-only 进程、独立镜像与 schema v2 K8s 清单已接线，但 publisher 在清单中仍默认关闭，且未执行真实 Test 集群 rollout。这些资产不代表 Redis、TLS Ingress、NAT、远程 Worker、Production publisher 或云部署已完成。

`config.ts` 只接受 `COMBO_ENVIRONMENT=test`、当前发布元数据、固定 Broker 数据库角色以及四个等长的 strict JSON profile 数组；数组按索引绑定 Worker、Codex artifact/schema 与 isolation，Worker version 重复或长度不等都会在创建数据库连接前失败。Broker contract digest 总是取 Protocol 包当前真源。`runtime.ts` 在监听 Worker 前验证最小角色与0019列合同，并在独立健康端口提供不含凭据和数据库错误的 `/health`、`/ready`。`processes/gateway.ts` 负责低敏启动事件和 SIGINT/SIGTERM drain。该启动面只启用 `conversation.open/ready`；Invocation projector 和 terminal sealer 缺失时原子拒绝，不能被健康探针掩盖。

Gateway PostgreSQL suite 还组合真实 Cloud projector 覆盖 confirmed `invocation.failed` 的 fresh admission、新 envelope exact replay与同 source body mutation；冲突事务保持原 FAILED Event/projection/Consumer terminal链不变，并复用统一 security isolation。0027-era 的“已有 durable SUCCEEDED chain 后收到 FAILED”fixture只证明generic terminal-type binding，不追溯冒充当时尚不可重构的完整succeeded fact；0028新增component与authority另行覆盖新SUCCEEDED事实和FAILED→SUCCEEDED反向冲突。Failed 路径的 terminal sealer 调用为零；SUCCEEDED fixture 的 sealer 只保持首次成功所需的一次调用。Gateway 本身没有 Host/Codex port，因此这些断言不能冒充 no-second-dispatch 证明，真实 Host counter 仍属于 Worker 纵向验收。

Full-succeeded PostgreSQL corpus进一步冻结FRESH仅sealer一次、新envelope使用新messageId/AAD/transport ciphertext但exact replay不二次sealing、fact mutation只写低敏alert并保持原Assistant Message/Event/Consumer Outbox/permanent receipt不变，以及FAILED→SUCCEEDED反向terminal-type conflict在sealer前隔离。测试sealer只实现opaque port contract，不是KMS；wire ciphertext/keyId/nonce/tag不进入alert或Gateway receipt。sealer throw与忽略abort均必须回滚Gateway frame/sequence和全部terminal事实。Gateway仍没有Host/Codex port，因此start command唯一与sealer次数不能冒充no-second-dispatch证明。
