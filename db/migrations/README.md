# 数据库迁移

本目录按文件名字典序保存 PostgreSQL 迁移。已应用的迁移不可修改，新增结构必须通过新的迁移文件演进。

`0016_creator_agent_invocation_lifecycle.sql` 追加 Worker Invocation prepared/started/succeeded 的 canonical fact digest、exact prepare/start Outbox authority、Execution Capability 期限与不可变绑定，并支持在 Gateway 已开启的同一 PostgreSQL 事务内投影 `PERSISTED/STARTING/RUNNING/SUCCEEDED`；Capability 首次签发、SECURITY 撤销和 Lease heartbeat 共用 exact Deployment advisory fence，跨 Consumer 撤销由单条 definer 完成，三个跨租户 `SECURITY DEFINER` 若不由 `SUPERUSER/BYPASSRLS` 角色拥有则迁移 fail closed。Execution Capability 的数据库上界是 Invocation `deadline_at + 30s`（legacy `NULL` 可升级，`+1ms` 即拒绝）。`combo_agent_api` 对 Invocation、Broker Outbox、Invocation Event 与 Message 的整表 `INSERT` 已撤销，只能以列级授权写入纯 `ACCEPTED`、初始 `invocation.prepare`、无 Worker fact 的 `invocation.accepted`，以及同一事务内由 deferred exact-chain guard 绑定上述三者的 USER Message；ASSISTANT Message 只允许 Broker terminal exact-chain。调用者 guard 同时覆盖未来继承 API/Broker role 的非特权登录角色。0012 遗留的 API Invocation `UPDATE` 列授权也全部撤销；在专门的 pre-dispatch cancel authority 落地前，API cancellation fail closed。`broker_outbox.command_id` 是跨连接重投也不得变化的 Broker envelope `messageId`。prepared 事实即使在途中越界仍 durable 落库，但 start Outbox 的最终写点会用 `clock_timestamp()` 重验 Invocation、Capability、Lease 与 command；started 在 `STARTING→RUNNING` 的最终 CAS 再验 deadline/Capability，越界则保留 fact 并进入 `RECONCILING/CANCEL_NOT_CONFIRMED`；terminal 在 sealer 返回后以同样的数据库实时钟重验 Capability，失败时整事务回滚。terminal Cloud Journal projector 只接收 authenticated Creator/Installation 与 wire fact/ciphertext：Consumer、Conversation、turn、Version、Lease/Fence 与 Capability 均从锁定的 Invocation 派生，fresh start command 与 Assistant Message ID 由 Cloud 生成；worker-session transport AEAD 必须经注入的解密 authority 后，再按 exact owner/conversation/message/role AAD 用 durable KMS key 重加密，不能把 wire ciphertext 直接写入 PostgreSQL。Worker 本地 ciphertext digest、wire transport cipher digest、durable message cipher digest 彼此独立；同一明文的 `combo:vnext:result:v1` result digest 与 `combo:vnext:message:v1` message content digest 也不得互换。transaction-scoped projector 将同一个 `AbortSignal` 传给每条 Gateway query 与 sealer；standalone `commit*` 只是测试/兼容包装器，不能替代 Gateway driver 的真实 query cancellation 与整体 transaction deadline。该 primitive 的通过不等于 Gateway/KMS 应用层纵向接线已经完成。

API Invocation `UPDATE` 全撤后，既有 Event sequence trigger 通过第四个 tenant-exact `SECURITY DEFINER` 保留 Invocation row lock；该函数同样受 `SUPERUSER/BYPASSRLS` owner gate 约束，并在 bypass RLS 前显式核对 `app.creator_id/app.consumer_id`。

`0017_creator_agent_conversation_ready_fact.sql` 以 immutable `conversation.open` command ID 作为稳定 `sourceEventId`，持久化完整 canonical `conversation.ready` fact、原 Session/connection/Lease/Fence、Version/Snapshot、Sandbox/Thread 与 evidence digest；exact replay 在所有 live authority 检查前命中，因此 ACK 丢失后即使 Worker 以新 Session/Lease/Fence 重连也能收敛。fresh late fact 仍要求原始绑定完整、Deployment ONLINE 且 generation/serving facts 收敛、Installation/Version 未撤销、Conversation OPENING、open command SENT；Version SECURITY 并发以统一 Deployment advisory + `NOWAIT`/`40001` 重试边界避免死锁。0014 的 transport-keyed projector 仅保留作升级审计，所有应用角色的执行权限已撤销。

`0018_creator_agent_broker_delivery_contract.sql` 是必须在 quiescent cutover 执行的 Broker contract migration：先以 `ACCESS EXCLUSIVE` 锁住 Outbox、outbound delivery、Gateway Session 和 Lease；任何 PENDING/SENT Outbox、非 `CLOUD_COMMITTED` business delivery、ACTIVE Session 或 ACTIVE Lease 都以 SQLSTATE `55000` 回滚整个 migration。它保留 nullable v0 行但禁止 v0 claim business command；`lease.revoke` 等 protocol control 仍可作为 exact v0 frame 持久化，并保持 control `messageId` 全局唯一。v1 `conversation.open` 保存可信 visible-transcript KMS HMAC 与非敏感 key metadata，并分别固定原始 Session/connection/Lease/Fence 和当前 retry Session/connection/Lease/Fence。business `messageId=command_id` 可跨 replacement Session 稳定重投，同一 Session 只投一次。Consumer 只能执行 `creator_agent_create_opening_conversation_v2`，旧 create-open 已撤权。

`0019_creator_agent_broker_outbox_publisher.sql` 只扩展默认关闭的 Test-only `conversation.open` publisher contract。它在发现任何无法补回 exact wire 时间的 v1 delivery 时以 SQLSTATE `55000` 回滚，然后为新 v1 delivery固定 PostgreSQL `wire_sent_at` 与 `wire_expires_at`，并新增只容纳标识符和 digest 的 `CLAIM_BROKER_COMMAND` operation receipt。replacement Worker 若在 current delivery 创建前先重放 SQLite PERSISTED ACK，Gateway frame receipt 只追加 acknowledged message UUID、ACK level 和 decision；三列全 NULL 是 migrate-first/旧 Gateway/rollback 的 expand 兼容分支，partial metadata 与非 ACK metadata 仍被拒绝。后续 claim 仍创建并发送 current re-envelope，但把 current delivery 初始化为 PERSISTED，且绝不据此 ACK Outbox。数据库 INSERT authority 硬性要求 current authenticated Session、current Lease/Fence、至少 3 秒 wire 窗口、ONLINE Test Deployment 与未过期 Outbox；Preview 和 Production 不能通过该 contract claim。

`0000_baseline_schema.sql` 建立当前基线。`0001_expired_upload_reconciliation.sql` 增加上传超时查询索引，`0002_drop_stream_events.sql` 拒绝旧 PostgreSQL 事件表，`0003_turns.sql` 增加自治轮次与轮内消息顺序。`0004_studio_sessions.sql`、`0005_capability_current_ui.sql` 和 `0006_one_running_turn_per_session.sql` 保存 Goal B 已发布的 Studio、current UI 与 Turn fencing 结构。

`0007_first_party_email_auth.sql` 仅允许空用户库切换到第一方邮箱验证码，并创建身份、验证码挑战、不透明会话与低敏审计表。`0008_application_database_roles.sql` 创建无登录的 API、worker 与 runtime 角色，撤销默认权限，并按当前服务职责授予最小表权限。`0009_billing.sql` 创建全局钱包、按用户与 Agent 隔离的免费额度、使用扣费、充值支付状态和不可变资金流水，以延迟约束守护账户、预留、业务终态与流水等式，并分别授予 API 与 Runtime 所需的最小权限。`0010_recharge_qr_channel.sql` 把扫码充值通道从聚合码 `aggregate_qr` 重命名为 C扫B 单渠道 `qr`（`/v3/prepay`），并迁移历史订单。`0011_recharge_qr_only.sql` 移除 H5「手机收银台」渠道，把历史 `h5` 订单迁到 `qr` 并把支付方式约束收窄为只允许 `qr`。`0012_creator_hosted_agent_vnext.sql` 增加 Creator-hosted Agent 的不可变 Snapshot/Version、Deployment/Lease、版本固定 Conversation、加密对话、Invocation/Event、Broker Outbox 与 Consumer replay Outbox 权威模型，强制 RLS、复合租户外键和专用服务角色。`0013_creator_agent_consumer_create.sql` 追加邀请制 Agent Access Grant、Conversation create 幂等、exact Lease/Fence 锁和 Consumer 最窄 RLS，并真实支持已有终态 Conversation 的 0012→0013 回填。`0014_creator_agent_consumer_open_ready.sql` 追加 Consumer-only 登录角色、normalized `conversation.open` Outbox binding、immutable ready receipt 与 exact current Lease/Fence/Worker projector。`0015_creator_agent_gateway_authority.sql` 追加一次性 Worker Challenge、持久 Session/sequence/receipt、安全事件、短 Lease 和 exact grant correlation authority。`0016_creator_agent_invocation_lifecycle.sql` 追加 durable Invocation fact/lifecycle authority。`0017_creator_agent_conversation_ready_fact.sql` 追加跨重连可重放的 durable conversation.ready fact authority。`0018_creator_agent_broker_delivery_contract.sql` 追加 quiescent v1 Broker payload/delivery 与 create-open-v2 authority。`0019_creator_agent_broker_outbox_publisher.sql` 追加默认关闭的 Test-only exact claim/retry receipt authority。已经执行的迁移不可修改，新结构必须继续追加编号。
