# 数据库迁移

本目录按文件名字典序保存 PostgreSQL 迁移。已应用的迁移不可修改，新增结构必须通过新的迁移文件演进。

`0016_creator_agent_invocation_lifecycle.sql` 追加 Worker Invocation prepared/started/succeeded 的 canonical fact digest、exact prepare/start Outbox authority、Execution Capability 期限与不可变绑定，并支持在 Gateway 已开启的同一 PostgreSQL 事务内投影 `PERSISTED/STARTING/RUNNING/SUCCEEDED`；Capability 首次签发、SECURITY 撤销和 Lease heartbeat 共用 exact Deployment advisory fence，跨 Consumer 撤销由单条 definer 完成，三个跨租户 `SECURITY DEFINER` 若不由 `SUPERUSER/BYPASSRLS` 角色拥有则迁移 fail closed。Execution Capability 的数据库上界是 Invocation `deadline_at + 30s`（legacy `NULL` 可升级，`+1ms` 即拒绝）。`combo_agent_api` 对 Invocation、Broker Outbox、Invocation Event 与 Message 的整表 `INSERT` 已撤销，只能以列级授权写入纯 `ACCEPTED`、初始 `invocation.prepare`、无 Worker fact 的 `invocation.accepted`，以及同一事务内由 deferred exact-chain guard 绑定上述三者的 USER Message；ASSISTANT Message 只允许 Broker terminal exact-chain。调用者 guard 同时覆盖未来继承 API/Broker role 的非特权登录角色。0012 遗留的 API Invocation `UPDATE` 列授权也全部撤销；在专门的 pre-dispatch cancel authority 落地前，API cancellation fail closed。`broker_outbox.command_id` 是跨连接重投也不得变化的 Broker envelope `messageId`。prepared 事实即使在途中越界仍 durable 落库，但 start Outbox 的最终写点会用 `clock_timestamp()` 重验 Invocation、Capability、Lease 与 command；started 在 `STARTING→RUNNING` 的最终 CAS 再验 deadline/Capability，越界则保留 fact 并进入 `RECONCILING/CANCEL_NOT_CONFIRMED`；terminal 在 sealer 返回后以同样的数据库实时钟重验 Capability，失败时整事务回滚。terminal Cloud Journal projector 只接收 authenticated Creator/Installation 与 wire fact/ciphertext：Consumer、Conversation、turn、Version、Lease/Fence 与 Capability 均从锁定的 Invocation 派生，fresh start command 与 Assistant Message ID 由 Cloud 生成；worker-session transport AEAD 必须经注入的解密 authority 后，再按 exact owner/conversation/message/role AAD 用 durable KMS key 重加密，不能把 wire ciphertext 直接写入 PostgreSQL。Worker 本地 ciphertext digest、wire transport cipher digest、durable message cipher digest 彼此独立；同一明文的 `combo:vnext:result:v1` result digest 与 `combo:vnext:message:v1` message content digest 也不得互换。transaction-scoped projector 将同一个 `AbortSignal` 传给每条 Gateway query 与 sealer；standalone `commit*` 只是测试/兼容包装器，不能替代 Gateway driver 的真实 query cancellation 与整体 transaction deadline。该 primitive 的通过不等于 Gateway/KMS 应用层纵向接线已经完成。

API Invocation `UPDATE` 全撤后，既有 Event sequence trigger 通过第四个 tenant-exact `SECURITY DEFINER` 保留 Invocation row lock；该函数同样受 `SUPERUSER/BYPASSRLS` owner gate 约束，并在 bypass RLS 前显式核对 `app.creator_id/app.consumer_id`。

`0000_baseline_schema.sql` 建立当前基线。`0001_expired_upload_reconciliation.sql` 增加上传超时查询索引，`0002_drop_stream_events.sql` 拒绝旧 PostgreSQL 事件表，`0003_turns.sql` 增加自治轮次与轮内消息顺序。`0004_studio_sessions.sql`、`0005_capability_current_ui.sql` 和 `0006_one_running_turn_per_session.sql` 保存 Goal B 已发布的 Studio、current UI 与 Turn fencing 结构。

`0007_first_party_email_auth.sql` 仅允许空用户库切换到第一方邮箱验证码，并创建身份、验证码挑战、不透明会话与低敏审计表。`0008_application_database_roles.sql` 创建无登录的 API、worker 与 runtime 角色，撤销默认权限，并按当前服务职责授予最小表权限。`0009_billing.sql` 创建全局钱包、按用户与 Agent 隔离的免费额度、使用扣费、充值支付状态和不可变资金流水，以延迟约束守护账户、预留、业务终态与流水等式，并分别授予 API 与 Runtime 所需的最小权限。`0010_recharge_qr_channel.sql` 把扫码充值通道从聚合码 `aggregate_qr` 重命名为 C扫B 单渠道 `qr`（`/v3/prepay`），并迁移历史订单。`0011_recharge_qr_only.sql` 移除 H5「手机收银台」渠道，把历史 `h5` 订单迁到 `qr` 并把支付方式约束收窄为只允许 `qr`。`0012_creator_hosted_agent_vnext.sql` 增加 Creator-hosted Agent 的不可变 Snapshot/Version、Deployment/Lease、版本固定 Conversation、加密对话、Invocation/Event、Broker Outbox 与 Consumer replay Outbox 权威模型，强制 RLS、复合租户外键和专用服务角色。`0013_creator_agent_consumer_create.sql` 追加邀请制 Access Grant、Conversation create 幂等、exact Lease/Fence 锁和 Consumer 最窄 RLS，并真实支持已有终态 Conversation 的 0012→0013 回填。`0014_creator_agent_consumer_open_ready.sql` 追加 Consumer-only 登录角色、normalized `conversation.open` Outbox binding、immutable ready receipt 与 exact current Lease/Fence/Worker projector。`0015_creator_agent_gateway_authority.sql` 追加一次性 Worker Challenge、持久 Session/sequence/receipt、安全事件、短 Lease 和 exact grant correlation authority。已经执行的迁移不可修改，新结构必须继续追加编号。
