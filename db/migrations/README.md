# 数据库迁移

本目录按文件名字典序保存 PostgreSQL 迁移。已应用的迁移不可修改，新增结构必须通过新的迁移文件演进。

`0030_creator_agent_runtime_product_wiring.sql` 接通默认关闭的 Test-only Runtime send/read 与 payload-v2 `invocation.prepare/start` transport。Consumer fresh send以短 preflight、事务外AEAD/P-256 authority、短finalize组成；finalize在统一Deployment advisory/Version NOWAIT锁序下原子提交USER/Invocation/Event/prepare Outbox，并由DB固定schema canonical helper重算完整Execution Capability digest。Runtime model、AgentVersion policy 与 Capability 共用同一 ASCII Model ID 语义；0030 撤销 Consumer 对旧 v1 accept wrapper 的执行权，只保留 create 与 v2 preflight/finalize 的 exact readiness。Gateway lifecycle delivery按current Session/Lease唯一，保存immutable canonical wire text + JSON projection + SHA-256；same-session replay复用exact bytes，replacement Session才新seal。Broker只通过ledger-free readiness与窄lock definer读取，claim receipt不含ciphertext。迁移只铺 nullable cancel字段但拒绝v2 cancel producer/claim；public cancel/retry仍fail closed，须由后续完整admission/projector/ACK迁移实现。

`0028_creator_agent_success_fact_admission.sql` 将`invocation.succeeded`切换到同一外层事务的DB preflight与finalize：preflight锁定canonical Worker fact并分配KMS AAD所需Assistant Message ID，finalize重验verified result、durable AEAD digest和Cloud deadline后一次提交Message/SUCCEEDED Event/Consumer chain/永久receipt/IDLE。Deferred constraints拒绝未消费seal intent或残缺terminal chain；failed v2在委托0027前对既有succeeded source做完整重构，旧success writers与Broker直调failed v1均被撤权。

`0027_creator_agent_failed_fact_admission.sql` 将confirmed `invocation.failed`的global source/terminal phase分类、DB JCS fact与Consumer payload/dedupe、FAILED/Event/Outbox/stream/receipt/Conversation原子链统一到Broker-only definer。永久append-only receipt支持Outbox retention后的exact replay；结构合法但不同的succeeded source只以generic stored-terminal binding参与security alert，不冒充完整succeeded fact重构。

`0026_creator_agent_started_fact_admission.sql` 把`invocation.started` Worker fact的global source/phase序列化、DB JCS digest、RUNNING/RECONCILING projection、Event component digests、late root与start ACK统一到Broker-only definer，并zero-legacy拒绝无法重构attestation component的旧started历史。

`0025_creator_agent_prepared_fact_admission.sql` 把`invocation.prepared` Worker fact的global source/Invocation phase序列化、跨RLS full-field classifier、DB-owned JCS digest、fresh PERSISTED Event与prepare ACK、exact replay及incoming-tenant alert统一到Broker-only definer。旧Broker direct persisted writer被cutover trigger拒绝；start command/late root仍由同一外层Cloud transaction继续。

`0024_creator_agent_reconciliation_source_admission.sql` 将explicit Reconciler root的全局logical-source锁、incoming tenant/row锁、跨RLS full-field compare、fresh root、exact replay与conflict alert统一到一个`SECURITY DEFINER`。它对direct、`late-prepared:`、`late-started:`来源做logical UUIDv7归一化唯一约束，并让旧Reconciler direct writer fail closed；冲突只返回固定outcome与incoming alert ID，不泄漏existing tenant/Invocation/body。CloudJournal必须在该outcome提交后才映射稳定security错误。

`0023_creator_agent_event_integrity.sql` 追加 reconciliation Event integrity building block：late-started 首次进入 RECONCILING 必须有唯一 root，既有 root 恢复 RUNNING 后再次进入 RECONCILING 必须追加独立、可幂等的 `invocation.reconciling_resumed`。Exact session/fact trigger与deferred companion constraint共同阻止Broker伪造及旧binary缺Event提交；迁移锁内zero-legacy门拒绝活动与可确定UNCERTAIN历史缺口，因此升级必须quiescent。迁移同时创建只保存控制ID、固定原因、canonical digest和可选order sequence的低敏 append-only alert表并强制RLS。它不回填无法无歧义识别的旧terminal history，不实现完整Event reducer/projection digest parity，也不把尚未接线的冲突alert冒充测试方案10.6闭环。

`0022_creator_agent_consumer_message_accept.sql` 把 0021 USER admission 收进 direct-login `combo_agent_consumer_api` 的单一 full-accept `SECURITY DEFINER`。Runtime 必须先从既有 `combo_runtime` UUIDv7 authority 取得 USER Message ID，才能把它绑定进未来 KMS AAD；Consumer wrapper 只接受该内部 ID、密文与 HMAC 摘要，并由数据库生成 Invocation、accepted Event、prepare Outbox 的 UUIDv7 和 pinned `maxTurnSeconds` deadline。Fresh accept 原子提交 Message、Invocation、Event、Outbox 与 Conversation BUSY/next-turn projection，并要求 Version 未被安全撤销、Deployment/Worker observed online、当前 Lease 与 Gateway 留有安全窗口；同 key 同 request digest 返回原 durable chain，同 key 不同 digest 返回 conflict，context limit 只保留 SUSPENDED marker。ADR-VNEXT-033 要求 HTTP fresh Consumer key 为 canonical lowercase UUIDv4；Message text authority同时检查canonical形式与版本，Conversation的PostgreSQL uuid trigger在类型规范化后只检查版本位。数据库继续保存1–256 text/uuid兼容形态，但非v4只有在既有durable row命中后才能replay/conflict。Consumer仍无任何业务表直接DML、public sequence或private admission wrapper权限。该E2 capability不创建AEAD、不证明Message ID的调用方来源，也不实现完整HTTP/header contract或dispatch。

`0021_creator_agent_context_admission.sql` 落地 ADR-VNEXT-006 的 Cloud-time PostgreSQL USER-admission primitive。它从 Conversation 锁定的 AgentVersion 读取 pinned `maxConversationTurns/maxVisibleHistoryBytes`，以连续 immutable USER Message 事实校验 `next_turn_no`，并在固定 `aes-256-gcm/v1`、tag 分列的前提下用既有 USER/ASSISTANT ciphertext octet sum 裁决下一条 USER。恰好等于 policy 可提交；N+1 只原子写低敏 `context_limit_reached_at` 和 `SUSPENDED`，不创建 Message、Invocation、Event 或任何 Outbox。`combo_agent_api` 不再有 Message column INSERT 或 Conversation projection UPDATE，只能执行窄 `creator_agent_admit_user_message_v1`；Broker 的 ASSISTANT terminal authority不变。fresh ASSISTANT 首次越过 history limit 的策略尚未冻结，因此完整 ADR-VNEXT-006 与 `SCH-004` 仍未完成。该迁移是 Test-only quiescent exact-release-tuple cutover，不是 rolling expand：必须先 drain/停掉旧 API writer，再以 migration+新 CloudJournal 同 tuple 发布；旧 binary 会 permission-fail，rollback 需要数据库恢复或 forward fix。公网 send-message route、HTTP 409 和 E3 不在此迁移范围。

`0016_creator_agent_invocation_lifecycle.sql` 追加 Worker Invocation prepared/started/succeeded 的 canonical fact digest、exact prepare/start Outbox authority、Execution Capability 期限与不可变绑定，并支持在 Gateway 已开启的同一 PostgreSQL 事务内投影 `PERSISTED/STARTING/RUNNING/SUCCEEDED`；Capability 首次签发、SECURITY 撤销和 Lease heartbeat 共用 exact Deployment advisory fence，跨 Consumer 撤销由单条 definer 完成，三个跨租户 `SECURITY DEFINER` 若不由 `SUPERUSER/BYPASSRLS` 角色拥有则迁移 fail closed。Execution Capability 的数据库上界是 Invocation `deadline_at + 30s`（legacy `NULL` 可升级，`+1ms` 即拒绝）。`combo_agent_api` 对 Invocation、Broker Outbox、Invocation Event 与 Message 的整表 `INSERT` 已撤销，只能以列级授权写入纯 `ACCEPTED`、初始 `invocation.prepare`、无 Worker fact 的 `invocation.accepted`，以及同一事务内由 deferred exact-chain guard 绑定上述三者的 USER Message；ASSISTANT Message 只允许 Broker terminal exact-chain。调用者 guard 同时覆盖未来继承 API/Broker role 的非特权登录角色。0012 遗留的 API Invocation `UPDATE` 列授权也全部撤销；在专门的 pre-dispatch cancel authority 落地前，API cancellation fail closed。`broker_outbox.command_id` 是跨连接重投也不得变化的 Broker envelope `messageId`。prepared 事实即使在途中越界仍 durable 落库，但 start Outbox 的最终写点会用 `clock_timestamp()` 重验 Invocation、Capability、Lease 与 command；started 在 `STARTING→RUNNING` 的最终 CAS 再验 deadline/Capability，越界则保留 fact 并进入 `RECONCILING/CANCEL_NOT_CONFIRMED`；terminal 在 sealer 返回后以同样的数据库实时钟重验 Capability，失败时整事务回滚。terminal Cloud Journal projector 只接收 authenticated Creator/Installation 与 wire fact/ciphertext：Consumer、Conversation、turn、Version、Lease/Fence 与 Capability 均从锁定的 Invocation 派生，fresh start command 与 Assistant Message ID 由 Cloud 生成；worker-session transport AEAD 必须经注入的解密 authority 后，再按 exact owner/conversation/message/role AAD 用 durable KMS key 重加密，不能把 wire ciphertext 直接写入 PostgreSQL。Worker 本地 ciphertext digest、wire transport cipher digest、durable message cipher digest 彼此独立；同一明文的 `combo:vnext:result:v1` result digest 与 `combo:vnext:message:v1` message content digest 也不得互换。transaction-scoped projector 将同一个 `AbortSignal` 传给每条 Gateway query 与 sealer；standalone `commit*` 只是测试/兼容包装器，不能替代 Gateway driver 的真实 query cancellation 与整体 transaction deadline。该 primitive 的通过不等于 Gateway/KMS 应用层纵向接线已经完成。

API Invocation `UPDATE` 全撤后，既有 Event sequence trigger 通过第四个 tenant-exact `SECURITY DEFINER` 保留 Invocation row lock；该函数同样受 `SUPERUSER/BYPASSRLS` owner gate 约束，并在 bypass RLS 前显式核对 `app.creator_id/app.consumer_id`。

`0017_creator_agent_conversation_ready_fact.sql` 以 immutable `conversation.open` command ID 作为稳定 `sourceEventId`，持久化完整 canonical `conversation.ready` fact、原 Session/connection/Lease/Fence、Version/Snapshot、Sandbox/Thread 与 evidence digest；exact replay 在所有 live authority 检查前命中，因此 ACK 丢失后即使 Worker 以新 Session/Lease/Fence 重连也能收敛。fresh late fact 仍要求原始绑定完整、Deployment ONLINE 且 generation/serving facts 收敛、Installation/Version 未撤销、Conversation OPENING、open command SENT；Version SECURITY 并发以统一 Deployment advisory + `NOWAIT`/`40001` 重试边界避免死锁。0014 的 transport-keyed projector 仅保留作升级审计，所有应用角色的执行权限已撤销。

`0018_creator_agent_broker_delivery_contract.sql` 是必须在 quiescent cutover 执行的 Broker contract migration：先以 `ACCESS EXCLUSIVE` 锁住 Outbox、outbound delivery、Gateway Session 和 Lease；任何 PENDING/SENT Outbox、非 `CLOUD_COMMITTED` business delivery、ACTIVE Session 或 ACTIVE Lease 都以 SQLSTATE `55000` 回滚整个 migration。它保留 nullable v0 行但禁止 v0 claim business command；`lease.revoke` 等 protocol control 仍可作为 exact v0 frame 持久化，并保持 control `messageId` 全局唯一。v1 `conversation.open` 保存可信 visible-transcript KMS HMAC 与非敏感 key metadata，并分别固定原始 Session/connection/Lease/Fence 和当前 retry Session/connection/Lease/Fence。business `messageId=command_id` 可跨 replacement Session 稳定重投，同一 Session 只投一次。Consumer 只能执行 `creator_agent_create_opening_conversation_v2`，旧 create-open 已撤权。

`0019_creator_agent_broker_outbox_publisher.sql` 只扩展默认关闭的 Test-only `conversation.open` publisher contract。它在发现任何无法补回 exact wire 时间的 v1 delivery 时以 SQLSTATE `55000` 回滚，然后为新 v1 delivery固定 PostgreSQL `wire_sent_at` 与 `wire_expires_at`，并新增只容纳标识符和 digest 的 `CLAIM_BROKER_COMMAND` operation receipt。replacement Worker 若在 current delivery 创建前先重放 SQLite PERSISTED ACK，Gateway frame receipt 只追加 acknowledged message UUID、ACK level 和 decision；三列全 NULL 是 migrate-first/旧 Gateway/rollback 的 expand 兼容分支，partial metadata 与非 ACK metadata 仍被拒绝。后续 claim 仍创建并发送 current re-envelope，但把 current delivery 初始化为 PERSISTED，且绝不据此 ACK Outbox。数据库 INSERT authority 硬性要求 current authenticated Session、current Lease/Fence、至少 3 秒 wire 窗口、ONLINE Test Deployment 与未过期 Outbox；Preview 和 Production 不能通过该 contract claim。

`0020_creator_agent_confirmed_failure_fact.sql` 在锁住 Invocation Event 写入后拒绝任何旧的、没有 canonical fact authority 的 Worker failure，再把 `invocation.failed` 扩展为 required fact digest、`sourceEventId=invocationId`、无 Broker command 的终态事实，并用固定 registry 拒绝未知或 authority/pre-dispatch 错误码。该迁移不改变 `invocation.cancelled`；没有 verified interrupt receipt producer/verifier 时，CANCELLED 仍不得 fresh commit。

`0000_baseline_schema.sql` 建立当前基线。`0001_expired_upload_reconciliation.sql` 增加上传超时查询索引，`0002_drop_stream_events.sql` 拒绝旧 PostgreSQL 事件表，`0003_turns.sql` 增加自治轮次与轮内消息顺序。`0004_studio_sessions.sql`、`0005_capability_current_ui.sql` 和 `0006_one_running_turn_per_session.sql` 保存 Goal B 已发布的 Studio、current UI 与 Turn fencing 结构。

`0007_first_party_email_auth.sql` 仅允许空用户库切换到第一方邮箱验证码，并创建身份、验证码挑战、不透明会话与低敏审计表。`0008_application_database_roles.sql` 创建无登录的 API、worker 与 runtime 角色，撤销默认权限，并按当前服务职责授予最小表权限。`0009_billing.sql` 创建全局钱包、按用户与
