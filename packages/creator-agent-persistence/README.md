# Creator Agent Persistence

本包实现 Creator-hosted Agent VNext 的云端持久化边界。`message-crypto.ts` 使用消息级 AES-256-GCM，并把 Creator、Conversation、Message、role 和 schema version 写入 canonical AAD；正文关联摘要使用 tenant key 的 domain-separated HMAC。production-facing `MessageKeyAuthority` 是opaque seal/open端口，不导出raw encryption/HMAC key；adapter必须内部生成CSPRNG nonce，并且只有在AES-GCM与`combo:vnext:message:v1` contentDigest都认证后才能返回OPENED。按owner/keyId轮换时旧key只以`DECRYPT_ONLY`读取，unknown或丢失旧key稳定进入`MESSAGE_KEY_UNAVAILABLE/BLOCKED`而不是返回空历史。raw-key crypto helper只供包内测试且不从package index导出。安全告警只携带owner、固定reason和domain-separated keyId SHA-256，不携带key、keyId原文、正文或provider error。`cloud-journal.ts` 在一个 PostgreSQL 事务中提交用户消息、Invocation、Event、Broker Outbox 和 Conversation projection；成功终态事务原子提交助手密文、终态 Event、Conversation IDLE、独立 Consumer Event Outbox 和 durable cursor。

ADR-VNEXT-006 admission 由 PostgreSQL `creator_agent_admit_user_message_v1` 独占 USER Message 与 Conversation `BUSY/next_turn_no` 写点。函数在 row lock 后用 `clock_timestamp()` 重验 deadline，读取 pinned AgentVersion policy，以连续 immutable USER rows 决定 turn count，并把固定 AES-GCM ciphertext octets（16-byte tag 分列）作为 USER/ASSISTANT visible UTF-8 byte count；candidate 不携带 byte count。达到 turn 或 byte N+1 时，transaction 只提交低敏、单调的 `SUSPENDED/context_limit_reached_at`，CloudJournal 在 COMMIT 后才抛 `CONVERSATION_CONTEXT_LIMIT`，因此 candidate Message、Invocation、accepted Event、Broker/Consumer Outbox 增量均为零。Internal `AcceptInvocationInput.turnNo=21` 只表达首个被拒绝的候选，公开协议与 durable Message 仍以 20 为上限。ADR-VNEXT-033 将 fresh `clientMessageId` public Zod冻结为canonical lowercase UUIDv4；既有DB列仍是1..256 text，以支持 durable legacy replay而不扩大fresh public contract。ASSISTANT terminal仍可能使已持久化sum首次越过64 KiB；fresh terminal的裁决策略尚未冻结，本tranche只实现ADR明示的“下一条USER admission”并保持完整ADR-VNEXT-006为未完成。该权限收窄是Test-only quiescent exact-tuple cutover，旧binary必须先停写；它不实现send-message HTTP route、409 wire mapping或E3。

Consumer Event publisher 使用 `FOR UPDATE SKIP LOCKED` 有界领取，按 cursor/digest 幂等确认发布；重连直接按 `Last-Event-ID` 从 PostgreSQL 顺序回放。七天 retention 删除与 `expiredThroughCursor` 在一个 Reconciler transaction 中推进，非零过期 cursor fail closed 为 `SSE_CURSOR_EXPIRED`。Redis/SSE 只是 commit 后的 at-least-once 投影，不保存权威 final，也不持久化 token delta。

`beginReconciliation` 只从有执行歧义的 durable 状态进入 `RECONCILING`，并把原因、首个 lost-evidence 云端时间和 append-only Event 原子绑定。`markUncertain` 在 PostgreSQL 判定该时间已满 300 秒后，才原子提交 `UNCERTAIN`、`EXECUTION_STATE_UNKNOWN`、终态 Event、Consumer Event Outbox/cursor 和 Conversation `IDLE`；截止前保持 `RECONCILING`，不会产生第二次 Host/Provider dispatch。相同 source event 可安全重放，原因、租户或 terminal source 不一致一律拒绝。

`projectSuccess`在canonical fact与transport常量校验后，把第一条业务SQL交给`0028`的Broker-only preflight：数据库先完成global Worker source与terminal classifier，再以私有transaction-bound seal intent返回Cloud生成的Assistant Message ID和derived Creator/Conversation/Message/role AAD。`EXACT`不访问transport decrypt或KMS；`SECURITY_BLOCKED`作为marker留在Gateway caller事务中提交；只有`SEAL_REQUIRED`在持有同一数据库锁期间调用sealer，并由caller signal与10秒hard deadline的本地settle race共同限制。Finalize消费exact intent后才原子提交Assistant密文、SUCCEEDED/Event、Consumer Outbox/stream、永久低敏receipt与Conversation IDLE，并在最终写点用`clock_timestamp()`重验Capability。`resultDigest`是authenticated transport plaintext的`combo:vnext:result:v1` HMAC，durable Message `contentDigest`是同一plaintext的`combo:vnext:message:v1` HMAC；Worker local、wire transport和durable Message三个cipher digest彼此独立，不得互换。数据库不持有HMAC/KMS key，因此“两个digest来自同一plaintext”仍由sealer端口证明，不能冒充数据库独立解密证明。旧succeeded Event没有可安全回填的`localResultCipherDigest`，所以`0028`是zero-legacy、Test-only quiescent cutover；升级前存在任何SUCCEEDED/terminal Assistant历史都会fail closed，而不是猜测重构。

`projectFailed` 只接受 canonical `invocation.failed` Worker fact、固定的 confirmed failure code、exact Version/Snapshot/Worker/原 Lease/Fence/Execution Capability 与 durable running authority。`0027` 的 Broker-only DB authority 原子提交 Invocation `FAILED`、Worker Event、Consumer terminal Outbox/cursor、stream、永久低敏 terminal receipt与Conversation `IDLE`，且不创建 Assistant Message；Cloud只解析outcome并在Gateway caller事务中返回`SECURITY_BLOCKED`marker，standalone wrapper则在alert提交后抛固定`JOURNAL_SECURITY_BLOCKED`。retained exact replay返回原cursor；普通Outbox删除后只有receipt cursor已被`expiredThroughCursor`覆盖才返回null，不因row缺失猜测retention。当前Worker仍尚无RUNNING Host-terminal failure producer，因此这只是fail-closed云端原语，不能宣称完整FAILED纵向链。Worker SQLite 与 RC Host 客户端已分别具备 structured interrupt receipt producer 和严格 terminal evidence building block，但尚无实际 Adapter 将两者纵向接线；本 Cloud/Persistence 包也仍无 fresh `projectCancelled` authority/verifier。cancel request或空RPC ACK不能冒充CANCELLED。

本包不持有 KMS 主密钥，不记录 Prompt 或答案，不把 Redis/WebSocket 当事实源。调用方负责在进入仓储前完成身份认证和Execution Capability验签；`MessageKeyAuthority`与`MessageKeySecurityAlertSink`只是KMS/keyring和durable audit的fail-closed端口，本仓库尚无真实KMS、90天轮换scheduler、备份恢复或durable alert adapter。仓储仍通过 transaction-local RLS identity、复合外键、Lease/Fence 精确绑定和数据库唯一约束再次校验；`(content_key_id, content_nonce)`在真实PostgreSQL中拒绝复用并回滚零事实。Consumer accept、Broker terminal/publisher 与 Reconciler retention 使用独立最小权限 PostgreSQL role/pool，不共用一个全能连接。
所有 deadline 判定以 PostgreSQL database clock 为权威，不依赖 API 主机时钟；事务稳定窗口使用 `now()`，锁等待后的 admission/final 写点使用 `clock_timestamp()` 再验。

Event Journal目前已强制连续sequence、source identity唯一、payload白名单、terminal后拒绝和append-only。`0023`补齐late-started root与唯一`invocation.reconciling_resumed`；`0024`把explicit begin-reconciliation的global logical-source classifier收进DB definer；`0025`接管`invocation.prepared`；`0026`接管`invocation.started`；`0027`接管confirmed `invocation.failed`；`0028`以transaction-bound seal intent接管完整`invocation.succeeded` fact、Assistant Message及其Consumer terminal receipt，并把failed-after-succeeded classifier升级为可重构的full binding。Prepared/started/succeeded/failed caller收到`SECURITY_BLOCKED`时不抛，而是在同一Gateway事务提交alert、frame/operation receipt与`CLOUD_COMMITTED/SECURITY_BLOCK` ACK；standalone wrapper只在alert提交后抛固定`JOURNAL_SECURITY_BLOCKED`。跨Consumer source复用、逐字段mutation、旧Broker writer、两类late root、failpoint、COMMIT ACK丢失与retention replay均由真实PostgreSQL覆盖。该闭环仍不覆盖cancelled/expired等terminal Event、journal-order alert、完整projection replay parity、alert审计读取/retention；无法无歧义识别的旧terminal history不回填，queue/lease/cancel/expiry writer尚未全部接线，不得据此关闭测试方案10.6。
