# 事实身份与交付证据

## 四层事实

| 层级     | 要回答的问题       | 最低记录内容                                                                   |
| -------- | ------------------ | ------------------------------------------------------------------------------ |
| 需求意图 | 应该实现什么       | 当前有效的用户指令、Issue、需求或产品契约，以及目标、非目标和完成标准          |
| 代码实现 | 哪一份代码实现了它 | 仓库、工作树、分支、基准引用、基准 SHA、当前 `HEAD` SHA 和工作树改动状态       |
| 运行环境 | 实际运行的是什么   | 环境名称、地址、进程当前目录、组件 SHA、启动时间、数据模式和登录模式           |
| 验收证据 | 实际观察到了什么   | 操作或命令、执行时间、对应 SHA、结果、覆盖范围、未验证项以及可复核的产物或链接 |

四层事实必须能够互相对应，但不能互相替代。需求意图定义“应该是什么”；实时代码、服务和测试只能证明“现在是什么”。任何层级发生冲突时停止扩大改动，报告冲突并请维护者确认。未知内容明确写为未知，不使用推测填补。

仓库已经采用 Active、Superseded、Archived 或类似状态管理产品契约时，只使用当前有效版本。旧文档没有明确替代关系，或多个文档同时声称生效时，不继续实现受冲突影响的页面、状态或跳转。

## 任务身份卡片

开始开发和每次交接时至少记录：

```text
任务 / 负责人：
需求真源 / 完成标准：
仓库 / 工作树：
分支：
基准远端与分支：
创建时的基准 SHA：
当前 HEAD SHA / dirty：
当前阶段：
已运行与待运行检查：
未提交 / 未推送状态：
拉取请求与阻塞项：
下一步 / 所需授权：
```

分支名、环境名和 URL 都会移动或复用。凡是声称某个版本已经验证、推送、检查、合并或运行，必须同时提供提交 SHA。

## 本地服务身份

从任务工作树启动服务前：

1. 检查目标端口是否已有进程，记录其 PID、完整命令和当前目录。进程不属于目标工作树时，先报告；未经授权不要停止其他任务的进程。
2. 记录工作树、分支、`HEAD` SHA、dirty 状态、各组件版本和启动时间。多组件系统还要确认 Web、API、Runtime 或等价组件的版本兼容关系。
3. 按仓库说明检查关键依赖和资源健康状态。不得用临时替代环境伪造正式测试证据。
4. 服务运行期间不要在该工作树切换分支。`HEAD`、依赖、配置或构建输入变化后，停止旧进程，重新构建并启动，再更新运行身份。

提供体验地址前，从公开入口实际进入本次目标结果，并验证任务要求覆盖的刷新、返回、重新登录或异步恢复路径。若仓库已有 `/__meta/build`、`/version.json`、Build 标识或部署元数据，核对其返回 SHA；URL 本身不是版本证据。不要仅为满足本规范而擅自增加生产接口。

## Real、Mock 与 Mixed

- `Real`：目标路径使用声明的真实服务和持久化数据。
- `Mock`：目标路径使用模拟服务、模拟登录、fixture 或非真实发布结果。
- `Mixed`：同一体验中同时存在真实与模拟组件，必须逐项列出边界。

Mock 必须显式标识，尽量使用真实 API schema 和可重复 fixture，并支持任务要求的刷新和重新进入。Mock 登录、Mock 发布和 Mock 数据不能描述成真实链路通过。静态视觉评审、Mock 完整流程和共享环境真实链路是不同证据，不能互相代替。

## 验收声明分级

按实际证据选择最窄的准确表述：

- **静态页面可评审**：只确认视觉或静态交互。
- **Mock 流程可体验**：端到端操作依赖 Mock，明确列出模拟部分。
- **局部真实链路已验证**：仅有声明的页面、服务或流程段使用真实服务走通。
- **完整真实链路已验证**：从约定入口到目标结果全程不手改 URL，且任务要求的刷新、离开、重新登录和异步恢复均已验证。

局部任务不强制验证整个产品主链路，但不得把局部证据描述成完整链路。

## 状态用语与最低证据

| 状态              | 最低证据                                             |
| ----------------- | ---------------------------------------------------- |
| 已开发            | 工作树、分支和修改文件                               |
| 已验证            | 实际命令或操作、结果和对应 `HEAD` SHA                |
| 已提交            | 本地提交 SHA                                         |
| 已推送            | 推送远端、远端分支和远端 SHA                         |
| 已创建拉取请求    | 拉取请求地址、基线、来源分支和当前提交 SHA           |
| 持续集成通过      | 拉取请求当前提交 SHA 对应的必需检查                  |
| 已合并            | 拉取请求 `MERGED` 状态、合并结果和规范上游基线 SHA   |
| 已部署            | 环境地址、部署记录以及服务实际返回或可核对的构建 SHA |
| Production 已发布 | 正式地址、Production 服务 SHA 和发布后冒烟结果       |

Commit 不能说成 Push，Push 不能说成 Merge，持续集成构建不能说成 Deploy，本地成功不能代替共享环境。记录部署证据不代表获得部署授权；部署、发布、路由和生产数据操作仍需遵守仓库政策和用户授权。
